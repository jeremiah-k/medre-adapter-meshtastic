# medre-adapter-meshtastic 0.1.1 release notes

This patch release documents the Meshtastic startup packet drain and the
reconnect receive watermark that landed after
[0.1.0](https://github.com/jeremiah-k/medre-adapter-meshtastic/releases/tag/0.1.0),
and archives the individual note behind the reconnect behavior. Release
preparation changes only version and documentation metadata; the qualified
runtime tree is unchanged. See the [archived individual
note](releases/0.1.1/reconnect-receive-watermark.md).

## Startup packet drain

After the first receive-ready connection of each adapter start, the session
arms a content-independent monotonic drain window immediately before enabling
receive callbacks. During `startup_packet_drain_seconds` (float, default
`15.0`; `0` disables), relay-classified packets reaching the started adapter
are dropped before `rxTime` evaluation, decode, staging or publication. BLE,
serial and TCP connections can deliver queued mesh packets without `rxTime`
or with an unsynchronized clock, and a Meshtastic radio hands its FROMRADIO
queue to the next successful connection; the drain keeps that backlog from
relaying as fresh traffic. A real message arriving during the interval is also
lost; drained packets are not replayed or retried, and the drain is a
heuristic, not proof that the node's queue is empty. Non-relay classification,
node information and native routing correlation are not gated. Each drop logs
at DEBUG, and the first subsequent relay packet at or after expiry closes the
window with one INFO summary. Diagnostics expose
`startup_drain_packets_dropped` and `startup_packet_drain_seconds`. (#54)

## Reconnect receive watermark

A transparent reconnect can hand the radio's pre-reconnect FROMRADIO queue to
the fresh connection. Every receive-ready installation now records a
receive-ready watermark per connection generation, and the `rxTime` gate
judges each packet against its own generation's watermark with
`startup_backlog_suppress_seconds` (default `5.0`; `0` disables) as the cutoff
tolerance. Timestamped pre-reconnect backlog is suppressed for the life of the
reconnected generation, while provably fresh traffic relays immediately — a
reconnect never spends a blind content-independent drain on live packets.

A fixed five-second, generation-scoped bootstrap window drops relay-classified
packets without a usable `rxTime` right after a reconnect: they cannot prove
they are not queue backlog. This is bounded, by-design loss — a few seconds of
unprovable-age packets per reconnect episode. After the window closes, missing
and malformed timestamps relay as before, because their age cannot be judged.
Future `rxTime` values are never suppressed: an ahead-of-host radio clock reads
as skew, not stale backlog, and a radio clock trailing the host by more than
the tolerance can suppress genuinely fresh packets.

No new configuration key: the bootstrap window shares the startup drain's
operator opt-out — `startup_packet_drain_seconds == 0` disables both the
initial drain and the reconnect window — and `startup_backlog_suppress_seconds`
remains the cutoff and radio clock-skew tolerance. Diagnostics add
`receive_ready_generation`, `reconnect_backlog_packets_dropped` and
`reconnect_receive_bootstrap_seconds`. The released 0.1.0 schema snapshots and
their freeze digests are unchanged. (#55)

## Qualification and dependencies

A bounded hardware short check between physical Meshtastic and LXMF radios —
one ordinary text message per direction, not full release qualification —
passed with the provider installed at `d17d70c` (#55); the two commits after
it change only Renovate tooling metadata. The focused physical reconnect
campaign (ordinary-message baseline, initial drain, replacement within drain,
timestamp classes, repeated generations, initial retry and reset, and both
opt-out modes) recorded its passing cases against an adapter install whose
tree is identical to `d17d70c`; raw campaign evidence stays private to the
hardware lab, and published records carry provenance only. Injected coverage
pinned the same behavior: deterministic session-double reconnect replay tests,
fake-adapter mirrors with constant parity against the real adapter module, and
the startup drain, fake drain, backlog and configuration suites.

Runtime dependencies are unchanged since 0.1.0: `mtjk==2.7.11.post14` and
`PyPubSub==4.0.7`. The adapter declares `medre>=0.1.0,<0.2.0` and installs
against published core 0.1.x releases (0.1.0 and 0.1.1).
